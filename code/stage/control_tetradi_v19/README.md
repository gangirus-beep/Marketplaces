# Контроль 50 — ещё не выполнен

manifest.json — план 50 обложек (47 товаров, включая пары квантов для проверки стабильности главного фото). Имена взяты из фактического реестра этапов 1–2. Не считать план готовыми файлами.

1. Прочитать media_rules.md и паспорт v27. Основной кадр — одна товарная единица поставщика; повторять по кванту нельзя.
2. Сверять товар по поставщику и коду, а не только по ID ВХ. В базе и старом реестре встречаются разные ID одного кода (например, 46728 / 778600, Самсон 103027); итоговый файл именовать по выбранной карточке реестра. Расхождения не исправлять массово в базе без отдельной задачи.
3. Подготовить реальные исходники и вырезки. Для ассорти cutmeta содержит main_img, main_ratio, variants, variant_mode (full/fragments/collage), при необходимости variant_title. Основной кадр НЕ коллаж и НЕ снимок прежней размноженной раскладки. Для набора кадр содержит один полный набор.
4. stage/render.py использует renderAssorti; при ассорти без main_img и variants завершится ошибкой, чтобы не подставить коллаж вместо одного товара. Универсальный cover.html показывает одну копию независимо от старых copies/layout. Для среды с запретом file:// использовать WB_COVER_URL и локальный HTTP-сервер со шрифтами и изображениями.
5. Сначала ровно 50 выбранных обложек. Если исходник для строки объективно недоступен, выбрать сопоставимую замену из того же разнообразия, записать изменение списка и причину. Не генерировать скрытые части. Самсон — последовательно, пауза >=2 секунд, кэш и остановка при 429.
6. Проверки: имена/размеры; одна товарная единица; квант и форма слова в плашке; состав набора; читаемость главного кадра и вариантов; полный текст вариативности выше 996 px и запас 120 px. Посмотреть все 50 готовых обложек и уменьшенные превью. У частой косой пока Т31 без полей; новый фон не утверждён.
7. Выдать ZIP, самостоятельный статический HTML с встроенными картинками и ZIP с этим HTML. Загрузить результаты на GitHub и дать HTTPS-ссылки; /workspace/output не является доставкой пользователю. Не считать локальное создание файлов передачей результатов.
8. После проверки владельца — согласованный полный перевыпуск тетрадей этапов 1–2. Следующие категории и П2 пока не запускать.
